# 開発者指摘対応 & カジノオーナー再レビュー

## 開発者対応

### 1. ログアウト時の幽霊プレイヤー対策
- 待機中/ゲーム終了後のログアウト時は部屋から正式退出してからセッションを破棄。
- 対戦中はセッションだけ消してゲームを破壊しないようログアウトを拒否。
- ゲーム終了後は `GameRoom.removePlayer` を許可。
- 終了後レスポンスは `GameRoom` の現在参加者を利用し、退出済みプレイヤーを残さない。
- UIもゲーム終了後は「退出」可能に変更。

### 2. 共通パスワード総当たり対策
- `LoginAttemptService` を追加。
- 接続元ごとに連続失敗回数を記録。
- 既定値: 5回失敗で60秒ロック。
- HTTP 429 + `Retry-After` を返却。
- 認証成功時に履歴を解除。
- 古い試行情報は定期削除し、メモリ増加を抑止。

### 3. JUnit標準配置への復旧
- 旧 `test/` 配下のテストを `src/test/java/` へ移動。
- `PlayValidator` / `Rule` / `RuleEngine` の現在シグネチャへ追従。
- JUnit4形式のstatic importをJUnit5へ統一。
- ログイン試行制限とGameRoomライフサイクルのテストを追加。

### 4. CSRF対策
- ログイン成功時にセッション固有CSRFトークンを発行。
- GET/HEAD/OPTIONS以外のAPI操作に `X-CSRF-Token` を要求。
- ブラウザ側はトークンを `sessionStorage` に保持し更新APIへ自動付与。

## 検証
- Java 21でゲームコア + Web/API層 + 全テストソースの型/構文チェック成功。
- `AuditFixSmoke` で以下を実行確認。
  - ログイン失敗上限到達後のロック
  - 認証成功後のロック解除
  - 対戦中の退出拒否
  - ゲーム終了後の退出許可
- 実行環境が外部ネットワークへ接続できないため、Gradle依存取得を伴う `./gradlew test` の実行のみ未確認。

## 残存する非ブロッキング課題
- 対戦中の通信断からの再接続機能は未実装。現在は対戦中ログアウトを拒否してゲーム破壊を防ぐ設計。
- サーバー再起動時に部屋/対戦状態は消える（インメモリMVP）。
- リバースプロキシ配下で公開する場合、ログイン試行制限の接続元IP判定がプロキシIPに集約されないよう転送ヘッダー設定を確認すること。
- 本番公開ではHTTPSを使用し `SESSION_COOKIE_SECURE=true` を設定すること。

## 最終判定

**身内/限定公開β: GO**

**一般インターネット公開: 条件付きGO**
- HTTPS
- Secure Cookie
- リバースプロキシ時の接続元IP設定確認
- 実環境で `./gradlew test` を通す

前回のP0/P1セキュリティ指摘は解消されており、現時点で公開を止めるコード上の致命的不備は再レビューでは確認できなかった。
