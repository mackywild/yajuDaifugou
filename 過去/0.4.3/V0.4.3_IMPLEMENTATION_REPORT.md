# Daifugo v0.4.3 Implementation Report

## 1. 対応目的

1. 野獣上がりの `8×1 + 10×N` 対応
2. Jバックの追加
3. Jバック/早漏カットインの全クライアント対応
4. CPU戦・マルチプレイ双方で同一ゲームコアを利用

## 2. 野獣上がり

`YajuRuleService` の開始条件を次の条件へ統一しました。

- 8がちょうど1枚
- 10が1枚以上
- その他のランクを持っていない
- 8を単体提出する

`EIGHT_PLAYED` 移行後は、残っている手札が全て10で、かつ全枚を同時提出した場合のみ成功です。

## 3. Jバック

`JackBackRule` を追加し、`GameState` に `jackBack` を保持します。

実効的な強弱判定は以下です。

```java
revolution ^ jackBack
```

`PlayValidator`、CPU合法手生成、CPUヒューリスティックは実効強弱状態を使用します。

場が流れると `GameState.clearField()` で以下を同時解除します。

- マーク縛り
- Jバック
- 早漏判定対象
- 早漏判定予約

## 4. 早漏イベント

Jバック適用後に3が最強となる場合だけ、次の実手番へ判定を予約します。

- 通常 → Jバック: 予約する
- 革命 → Jバック: 予約しない

7渡しが介在する場合は、7渡し完了後に実際の次手番プレイヤーへ予約します。

早漏判定状態は合法プレイが確定する前には消費しません。野獣ルール等でカード提出が拒否された場合、判定権は維持されます。

## 5. UI

`JACK_BACK` / `EARLY_SHOT` を既存の共有ゲームイベントへ統合しました。

Androidではカットイン中にCPU自動進行を停止し、演出が裏で流れないようにしています。

## 6. N-GOD互換性

既存MLPはJバック導入前に学習されています。
特徴量 `f[7]` は従来の革命フラグから実効強弱反転フラグへ変更しました。
Jバックの存在しない旧学習データでは両値が同一のため、次元数・重み配列を変更せず互換利用できます。
