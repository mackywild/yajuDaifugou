# Casino Audit Fix Report

## 判定
監査で指摘したP0/P1をMVP範囲で修正しました。

## 対応済み
- [x] playerIdを本人証明として扱わない
  - `/state`, `/start`, `/play`, `/pass`, `/leave` はHTTPセッションからプレイヤーを特定
  - ブラウザからplayerIdを送信・localStorage保存する処理を削除
- [x] 共通パスワードのデフォルト値を廃止
  - `DAIFUGO_PASSWORD` 未設定時はアプリ起動を拒否
  - UIから初期パスワード表示を削除
  - ログイン成功時にSession IDを変更
- [x] 状態取得も部屋ロック内でDTO化
  - ゲーム更新途中の中間状態を返しにくい構造へ修正
- [x] 8切り上がり禁止を復旧
- [x] スペード3上がり禁止を復旧
- [x] ホスト権限を追加
  - 最初の参加者をホスト化
  - ゲーム開始はホストのみ
  - 開始前にホストが退出した場合は次の参加者へ移譲
- [x] 退出APIを追加
  - ゲーム開始前のみ退出可能
  - 0人になった部屋は削除
- [x] ルームTTLを追加
  - 既定30分無操作で削除
- [x] 未使用WebSocket設定を削除
  - 現行MVPはREST + 1秒ポーリングへ一本化

## 検証
- Java 21でゲームコアを直接コンパイル: OK
- ホスト移譲 / 8上がり禁止 / スペ3上がり禁止のスモーク実行: OK
- Spring/Jakarta APIを最小スタブ化したWeb層型チェック: OK
- Gradle本体のオンライン取得は実行環境のネットワーク制限により未実施

## 公開時の追加推奨
- HTTPS + `SESSION_COOKIE_SECURE=true`
- ログイン試行回数制限
- Spring Securityによる認証・CSRF・認可の統合
- ゲーム中の切断/再接続
- 監査ログ
- Redis等による複数サーバー対応
