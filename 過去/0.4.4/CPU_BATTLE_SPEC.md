# Daifugo v0.4.4 CPU戦【ひとりでイク】仕様

## 1. 目的

CPU戦は1人でもゲームルールを遊べるモードであると同時に、マルチプレイ前に大量のゲーム進行を発生させてルール組み合わせの不具合を早期発見する検証基盤として使用する。

## 2. 遷移

```text
Login
  ↓
Main Menu
  ├─ マルチプレイ
  └─ 【ひとりでイク】
          ↓
      CPU戦設定
          ↓
      即ゲーム開始
```

## 3. CPU人数

- CPU 1〜7人を選択可能
- 人間1 + CPU1 = 2人戦
- 人間1 + CPU7 = 8人戦

CPU戦には常に人間プレイヤーを1人含み、総人数は2〜8人とする。

## 4. 難易度

### 簡単
合法手からランダム寄りに選択する。勝利最適化をほぼ行わず、初心者が勝ちやすい強さを狙う。

### 普通
カード枚数削減、弱いカードからの消費、禁止上がり回避、野獣上がり等の基本評価を行う。25%程度は探索的な手を選び、人間らしいミスを残す。

### 難しい
普通の評価に加え、他プレイヤーの残り枚数、終盤、手札のペア/トリプル構造、8切り、7渡し、強札投入タイミングを考慮する。

### N-GOD
自己対戦で学習したニューラル評価器で合法手を評価する最上位CPU。未学習のルール組み合わせでも破綻しにくいよう、難しいCPUのヒューリスティックを安全項としてブレンドする。

## 5. CPU戦ルール設定

対戦開始前に以下を設定する。

- CPU人数
- CPU難易度
- ジョーカー枚数 0〜2
- 革命
- 8切り
- マーク縛り
- 7渡し
- 野獣ルール
- Jバック
- 禁止上がり

野獣ルールON時は8切りを自動ONにして変更不可とする。サーバー側でも不正な組み合わせを拒否する。

## 6. CPU自動進行

Web / iOSのCPU戦では、人間がカード提出 / 7渡し / パスを行った後、現在手番がCPUなら人間の手番またはゲーム終了までサーバーがCPU操作を連続実行する。

AndroidのローカルCPU戦では同じJavaゲームコアをAPK内で直接実行し、CPUを1手ずつ進めて演出する。どちらも同一のGameEngine / PlayValidator / LegalMoveGeneratorを使用する。

## 7. 合法手生成

CPUは手札から以下を列挙し、既存`PlayValidator`と野獣ルールで合法手だけに絞る。

- SINGLE
- PAIR
- TRIPLE
- FOUR
- STRAIGHT
- PASS（場が空でない場合）

7渡し中は必要枚数の組み合わせを列挙し、野獣対象者が最後の8/10を手放す候補を除外する。

## 8. N-GOD学習

- 特徴量: 38
- 教師: ゲーム終了時の順位を0〜1へ正規化したMonte Carlo報酬
- データ: 5,000ゲーム、278,188 state-action
- MLP: 38 → 32(ReLU) → 16(ReLU) → 1(Sigmoid)
- 学習: AdamW / MSE
- 乱数seed: 8101919

学習済みモデルは`NgodNeuralModel.java`へ数値配列としてexportしているため、ゲームサーバー稼働時にPythonやPyTorchは不要。

## 9. ベンチマーク

対象CPU1体 + 難しいCPU3体、座席をローテーションし4,000ゲームずつ実施。

| CPU | 1位率 | 平均順位 | deadlock |
|---|---:|---:|---:|
| 簡単 | 5.3% | 3.309 | 0 |
| 普通 | 23.0% | 2.503 | 0 |
| 難しい | 25.9% | 2.485 | 0 |
| N-GOD | 31.3% | 2.173 | 0 |

## 10. 今後の学習強化候補

v0.4.4時点のN-GODは「state-actionから最終順位価値を予測する評価器」。今後は以下を追加できる。

- 対戦ログの継続学習
- 相手の出したカード履歴
- 残存カード推定
- ルール別モデル / curriculum learning
- MCTSとの組み合わせ
- N-GOD同士の世代更新

## 11. v0.4.4 8人戦対応

- CPU人数: 1〜7人
- 総人数: 2〜8人
- 8人時も順位1〜8位を重複なく確定
- Androidは7CPUを横スクロールで選択
- Android対戦画面は最大7人の相手を横スクロール表示
- iOS対戦画面も最大7人の相手を横スクロール表示
- 自己対戦データ生成器は2〜8人を生成対象に拡張

既存N-GODの学習済み重み自体は4人戦中心の既存データを維持している。8人戦でも合法手選択・完走は確認済みだが、5〜8人戦での強さ指標は別途再学習・再ベンチマーク対象とする。

## AndroidローカルCPU戦（重要）

Android版の【ひとりでイク】はSpring Bootサーバーへ接続しない。
アプリ起動直後にメインメニューを表示し、以下の2系統を完全に分離する。

- マルチプレイ: サーバーURL/パスワード入力 → Spring Bootへログイン → 部屋作成/参加
- 【ひとりでイク】: CPU設定 → 端末内GameEngineを直接起動 → オフライン対戦

CPU戦ではREST/WebSocket/HTTPセッションを使用しない。既存JavaゲームコアをAndroidの
`:gamecore` モジュールとして直接組み込み、CPU思考・N-GOD・特殊ルールも端末内で実行する。
この構成により、サーバー停止中・圏外・機内モードでもCPU戦でゲームロジックの回帰確認ができる。


## v0.4.1 CPU行動演出

CPU戦ではCPU行動を即時連続処理せず、1手ごとにUIへ公開する。

- PLAY: 選択カードを公開し、約3秒で手元側から場へ移動
- PASS: 約1.5秒表示
- 7渡し: 選択カードと譲渡先を約2秒表示
- CPU行動中は人間の操作を禁止
- 直近6手のCPU行動ログを保持

ゲームコアの判定結果そのものは演出開始時点で確定するが、画面へのGameState反映は演出終了後に行う。
これによりロジックを変更せず、プレイヤーがCPUの行動を追跡できる。


## v0.4.2 対戦UI

- CPU/対人相手の残り手札は裏向きカードの実枚数で表示する
- 7渡し中のカードは第三者へ内容を公開せず裏向きで表示する
- 7渡しログはカード内容を記録せず、枚数のみ記録する
- プレイヤーアイコンは席順ベースで一意に割り当て、同一卓で重複させない
- 野獣対象確定時は初期配牌/7渡し途中確定とも全画面カットインを表示する
- CPU行動ログは直近6件を保持する


## v0.4.3 Jバック

- CPU戦設定からJバックをON/OFF可能
- Jが出ると場が流れるまで実効強弱を反転する
- 実効強弱は `革命 XOR Jバック`。通常状態のJバックでは3が最強、革命中のJバックでは2が最強
- 合法手生成は `GameState.isStrengthReversed()` を利用してJバック中も正しい候補だけを列挙する
- N-GODの既存特徴量 `f[7]` は革命そのものではなく実効強弱反転状態を入力するよう変更。Jバック導入前は両者が同値だったため、学習済み重みとの互換性を維持する
- Jバック直後の「早漏」判定は通常状態で3が最強になる場合のみ対象
